# Adversarial UI/UX review — MissionControl web UI

Date: 2026-09-26 · Scope: `src/web/` (shell + backlog/board/list/detail) ·
Method: screenshot walkthrough of all four views at 1440×900 and 390×844 in
both themes, code review against the Vercel Web Interface Guidelines
(guidelines audit run as a separate pass over every file), and CDP layout
probes for overflow/focus/behaviour.

## Verdict

The critique "cheap, Bootstrap v1" was directionally right, but the cause was
not one big mistake — it was six small habits compounding:

1. **Everything was a bordered box.** Chips, cards, tables, panels, selects and
   buttons all carried a full 1px border, so hierarchy was done by borders
   alone and nothing receded. Visual weight was uniform; the eye had nowhere to
   rest. (Design-system: `components.css`.)
2. **Redundant controls everywhere.** Every board card rendered a full-width
   status `<select>` that repeated the column the card was already sitting in —
   8 cards in "To do" each announced "To do" in a dropdown, ~40px of dead height
   per card. The backlog had the same instruction twice (top hint + bottom
   note). All work wrapped four compact selects in a labelled bordered panel
   with a legend, a fieldset and a heading for what is one toolbar row.
3. **Full-width everything.** The base `input, select { width: 100% }` rule
   stretched the backlog's type dropdown across ~1100px — the single worst
   "cheap" signal in the UI.
4. **Chip inflation.** Type chips carried a letter mark *plus* the full word,
   in three places per screen; the comment count was a chip; the agent flag was
   a chip. A board card's first row could hold five bordered chips before the
   title.
5. **Action clutter.** Four move buttons per backlog row — 28 bordered buttons
   on screen at once, most structurally disabled (no previous sibling, already
   at root) most of the time.
6. **Form-filed detail page.** "Work item #2" + "Title" label + a giant title
   input read like a CRUD form, not a document; a destructive "Delete item" sat
   as a plain bordered button equal in weight to navigation.

Plus one real bug class: an `.sr-only` `<legend>` inside a `<fieldset>`
overflows its fieldset (legends are layout-special) and forced a horizontal
page scrollbar on All work — visible in "before" captures as a stray scrollbar.

## What was changed

Design system (`design-system/`):

- **Tokens** re-based on a Primer-style neutral ramp: page canvas (`canvas-subtle`)
  darker than card surfaces, two-step borders (`border-default` / a much softer
  `border-muted`), 6/8/12px radii instead of 2/4/6, subtle shadows, GitHub-flavoured
  semantic hues, coherent dark set (`#0d1117` page / `#161b22` cards). No token
  renames — every `--wb-*` name survives, so the token contract tests pass unchanged.
- **Buttons** demoted to Primer-style: medium weight, quiet fill, border only where
  needed; primary filled; **danger is now a ghost** (quiet red text, fills on hover)
  since the irreversible step is already guarded by `confirm()` in the detail hook.
- **Chips are borderless tinted pills** (11–12px), comment count renders as muted
  text, agent chip shrunk, type mark 14px.
- **Inputs** lost their inset shadow and go through the softer border.

Views:

- **Board** — per-card status select moved into the card footer as a *ghost
  select*: width fits its options, borderless until hover, tinted in the
  column's status colour. Still the same native `<select>` with the same
  accessible name (`Move #N to status`) and focus target, so keyboard/AT
  behaviour is unchanged. Columns: thick painted top borders → small status
  dot; `min-height: 28rem` → 18rem so one-card lanes stop broadcasting empty
  space; sunken column surface so cards read as raised; quiet "Add" text
  button; count badge with tabular numerals.
- **Backlog** — the "Add backlog item" card became a borderless toolbar row
  (type select auto-width + flexible input + primary button, one hint line);
  the duplicated bottom note is gone. Cell padding 12/16 → 8/12. The four move
  buttons are now ghost icon buttons that **reveal on row hover or keyboard
  focus** and stay permanently visible on `(hover: none)` layouts; they remain
  focusable at all times (only their paint is deferred), so the tab order and
  screen-reader behaviour do not depend on the pointer.
- **All work** — filter fieldset became a one-row quiet toolbar; legend and
  field labels moved to `sr-only`/`aria-label` (all strings still ship, the
  bundle contract tests still pass); each ghost select self-describes with its
  first option ("All statuses"). Table scroller softened to match.
- **Detail** — "Work item #2" demoted to a small eyebrow above a 24px inline
  title; visible "Title" label → `sr-only`; "Delete item" ghost; created/closed
  timestamps are real `<time>` elements; `detail-layout` uses `align-items:
  start` so a short description stops stretching into a big empty box;
  "Set parent" no longer wraps.
- **Shell** — nav active state keeps the underline, drops the filled background;
  topbar border softened; `theme-color` meta added for both schemes (kills the
  white flash band on mobile).

Guidelines-audit fixes folded in: board error banner now `role="alert"`;
login error takes focus on failure; `spellcheck=false` and `…`-terminated
placeholder on the token field; trailing `…` on detail placeholders;
`autoComplete="off"` + `name` on the parent/subtask/relationship inputs; the
relationship-item error is wired via `aria-describedby` + `role="status"`;
`translate="no"` on inline `<code>`; `touch-action: manipulation` on all
controls; intentional `-webkit-tap-highlight-color`; skip-link uses
`:focus-visible` too; `text-wrap: balance` on headings.

Verified: `bun run typecheck` clean, `bun test` 575/575 (the static asset
contract — pinned class names, ARIA strings, CSS rules — passes unchanged),
and CDP probes show zero horizontal overflow on all four views in both
themes; before/after screenshots in `.tmp/mcshot/`.

## Deliberately not changed

- **Sentence case button copy.** The guidelines ask for Title Case buttons, but
  the codebase (and its test contract: `"Sign out"`, `"Delete item"`) uses
  sentence case consistently. Consistency won; flipping one surface to Title
  Case while tests pin the rest would create a third style.
- **Delete confirmation stays `window.confirm()`.** Two-step buttons on top of
  a native confirm would be double confirmation. A styled modal is nicer, but
  that is a component-infrastructure decision, not a pass over existing views.
- **Sign out is still immediate.** Losing a local read-only session is not a
  destructive act in the guideline sense; a confirm would be noise.
- **Raw ID inputs for parent/relationships.** A real picker needs a searchable
  item list endpoint contract on top of `my_work`/`list_work`; the inputs now
  at least validate inline and announce their errors.

## Remaining work (ranked)

1. **Virtualization.** The backlog renders an uncapped envelope and the list
   grows via "Load more"; both `.map()` without `content-visibility: auto`.
   Fine at hundreds of items, wrong at thousands. Rows are the right unit for
   `content-visibility: auto; contain-intrinsic-size: auto 3.5rem;` — cheap,
   no JS.
2. **The backlog drag code reads `getBoundingClientRect()` per `dragover`.**
   Cache the row rect on dragenter/scroll or throttle to animation frames.
3. **Label chips could use the label's own colour** (the API already returns
   `color` for detail labels) — needs the colour plumbed into list/backlog
   DTOs first.
4. **Parent/relationship pickers** over raw IDs (above).
5. **`getBoundingClientRect`-free sticky interactions**: the backlog drop mode
   check can stay, but board drag could carry the same one-rect-per-drag
   pattern.
